# Ansible Automation Platform ハンズオントレーニング

## 概要

* **目的:** Ansible Automation Platform (AAP) の画面操作を、Linux と Windows へのファイル配置を題材にして学ぶ
* **最初に読む:** [AAPのしくみ](./aap_overview.md)。メニューと、ジョブテンプレートがどの部品の組み合わせかを説明しています
* **目的から探す:** 使いたい機能や困りごとが決まっている方は [やりたいことから探す](#やりたいことから探す) から章を選べます
* **対象:** Ansible を少し使ったことがあり、AAP は初めての方（運用担当者を含む）
* **前提:** Playbook の `hosts`、`tasks`、モジュール、変数の読み方が分かること。AAP の用語と操作はこの資料だけで進めます
* **前提環境:** AAP 2.5 以降（画面確認は 2.7 の日本語UI）、GitLab（画面確認は 19 の英語UI）。いずれも構築済みで、ユーザーも作成済み
* **共有:** 1つの AAP と GitLab、同じ Linux と Windows を複数人で同時に使います。作る認証情報、ジョブテンプレート、サーバ上のディレクトリには [演習1](./basic-intro/ex1.md) の接頭辞 `<name_prefix>` を付け、名前が重ならないようにします。終わったら [削除手順](./cleanup.md) でその接頭辞のついたリソースをまとめて消します

## 事前準備

→ [事前準備（確認リスト）](./prepare_training_environment.md)

本資料は AAP と GitLab が構築済みであることを前提にしています。AAP 自体のインストール手順は含みません。

## やりたいことから探す

頭から順に進める場合は、下の [どの演習をやるか](#どの演習をやるか) を見てください。ここは、使いたい機能や困りごとから章を探すための一覧です。

### 土台になる章

ほかの章は、ここで作るものを使います。AAP の1回の実行は「どの Playbook を」「どのサーバに」「どのログイン情報で」の組み合わせで、それを1つずつ作るのが下の章です（詳しくは [AAPのしくみ](./aap_overview.md)）。

| 章 | 何ができるか | なぜ先に必要か |
|---|---|---|
| [演習1 ログイン](./basic-intro/ex1.md) | 画面の構成を知り、自分の接頭辞を決める | 1つの AAP を複数人で使うため、以降に作るものの名前は全部この接頭辞で分けます |
| [演習2 認証情報](./basic-intro/ex2.md) | サーバと GitLab へのログイン情報を AAP に保存する | 「どのログイン情報で」にあたります。ジョブはこれでサーバに入り、GitLab を読みます |
| [演習3 インベントリー](./basic-intro/ex3.md) | 対象サーバの一覧を作り、AAP から届くか確かめる | 「どのサーバに」にあたります |
| [演習4 AWSでサーバを作る](./basic-intro/ex4.md) | 練習用の Linux と Windows を AWS に作る | 対象サーバが無い場合だけ必要です |
| [演習5 GitLab](./basic-controller/ex5.md) | Playbook を GitLab に置き、AAP から読めるようにする | 「どの Playbook を」にあたります |
| [演習7 ジョブテンプレート](./basic-controller/ex7.md) | 上の3つを組にして、画面から実行する | ほとんどの章は、ここで作るジョブテンプレートに機能を足していきます |

## どの演習をやるか

この学習で作る認証情報、インベントリー、プロジェクト、ジョブテンプレート、GitLab のプロジェクト、AWS で作ったサーバは、最後に [削除手順](./cleanup.md) で消します。名前は各演習に書いてあるものを使います。

対象の Linux と Windows がすでにある場合と、AWS で新しく作る場合で、やる演習が一部違います。次のどちらかの順に進めてください。

既存サーバを使用する場合: 演習1 → 2 → 3（Section 3 は飛ばす）→ 5 → 6 → 7 → 8 → 9 → 10 → 11 → 応用。

サーバが無い場合: 演習1 → 2 → 3（Section 1、2、3）→ 4 → 3（Section 4、5）→ 5 → 6 → 7 → 8 → 9 → 10 → 11 → 応用。

| 演習 | 既存サーバを使用 | AWSで新しく作る |
|---|---|---|
| [1 ログイン](./basic-intro/ex1.md) | 実施 | 実施 |
| [2 認証情報](./basic-intro/ex2.md) | 実施 | 実施。サーバのログイン情報は演習4の Section 4 で作る |
| [3 インベントリーと疎通](./basic-intro/ex3.md) | 実施。Section 3 は飛ばす | Section 1から3を実施。ホスト登録は演習4のあと |
| [4 AWSでサーバを作る](./basic-intro/ex4.md) | **飛ばして演習5へ** | 実施。終わったら演習3の Section 4 へ戻る |
| [5 GitLab](./basic-controller/ex5.md) | 実施 | 実施。演習4で作ったプロジェクトに残りのファイルを足す |
| [6 インベントリソース](./basic-controller/ex6.md) | 実施 | 実施 |
| [7 ジョブテンプレート](./basic-controller/ex7.md) | 実施 | 実施 |
| [8 Survey](./basic-controller/ex8.md) | 実施 | 実施 |
| [9 Vault](./basic-controller/ex9.md) | 実施 | 実施 |
| [10 スケジュール](./basic-controller/ex10.md) | 実施 | 実施 |
| [11 ワークフロー](./basic-controller/ex11.md) | 実施 | 実施 |
| [応用1 チームとロール](./advanced/ex1.md) | 実施 | 実施 |
| [応用2 通知](./advanced/ex2.md) | 環境内のメールサーバ | `lin1` に入れる検証用メールサーバ（Mailpit） |
| [応用3 カスタムEE](./advanced/ex3.md) | AAP サーバへ SSH でき、ベースイメージとコレクションを取得できるときだけ | AAP サーバへ SSH できるときだけ |

既存サーバを使用する環境では、演習中にインターネットへ出ません。コレクションとコンテナイメージは、AAP に入っているものを使います。例外は応用演習3で、ベースイメージとコレクションを取得するために接続が必要です。AWS でサーバを作る場合は、インターネットへ出られます。

作るファイルは次の2か所です。ディレクトリは Playbook が作ります。

| OS | ファイル |
|---|---|
| Linux | `/tmp/<name_prefix>-aap-training/note.txt` |
| Windows | `C:\temp\<name_prefix>-aap-training\note.txt` |

Windows への接続方式は PSRP です。ドメインに参加していない Windows（AWS で作るサーバを含む）は NTLM、ドメインに参加している Windows は Kerberos を使います。

## 対象バージョン

* AAP 2.5 以降（統合UI: **Automation Execution** / **Automation Decisions** / **Access Management**）
* SCM: GitLab。ファイルの編集は Web IDE を使います
* カスタム Execution Environment は、AAP サーバの `/tmp/<name_prefix>-custom-ee` で作ります。SSH するユーザーは [事前準備](./prepare_training_environment.md) で控えます
