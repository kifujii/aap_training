# 応用演習 11 - GitLab連携の応用

この演習では、GitLabへのpushをトリガーにAAPのProjectを自動Syncする設定と、GitLab CI/CDパイプラインからAAPを操作する連携方法を学びます。

**前提条件:** [基礎演習4](../basic-controller/ex4.md)、[応用演習7](./ex7.md)を完了していること

[前に戻る](./ex10.md)

## Section 1: ProjectのWebhook自動Sync設定

[基礎演習4](../basic-controller/ex4.md)では、`Update Revision on Launch` を使ってJob実行時に最新リビジョンを取得していました。ここでは、GitLabへのpush時点で即座にSyncが走るように設定します。

### Step 1: AAP側でWebhookを有効化する

`aap-training-content` Projectの編集画面を開き、「Enable Webhook」を有効化して保存します。保存後、画面に以下の情報が表示されます。

* **Webhook URL**: GitLab側に登録するURL
* **Webhook Key**: GitLab側で送信元を検証するためのシークレットキー

これらを控えておきます。

### Step 2: GitLab側にWebhookを登録する

GitLabのProject画面 →「Settings」→「Webhooks」を開き、以下を入力します。

| 項目 | 入力値 |
|---|---|
| URL | Step 1で確認したWebhook URL |
| Secret Token | Step 1で確認したWebhook Key |
| Trigger | `Push events` にチェック |

「Add webhook」をクリックして保存します。

### Step 2: 動作確認する

`sample-content` の内容を少し変更して（例: `group_vars/all.yml` の `sshd_client_alive_interval` を変更）GitLabにpushします。

```bash
$ git add group_vars/all.yml
$ git commit -m "Adjust sshd client alive interval"
$ git push
```

push後、数秒以内にAAPの `aap-training-content` Project詳細画面の「Jobs」履歴に、自動的に新しいSyncが実行されていることを確認してください。[基礎演習4](../basic-controller/ex4.md)で手動クリックしていたSyncが、GitLabへのpushをトリガーに自動化された状態です。

**Note:** GitLab側の「Recent Deliveries」（Webhook配信履歴）で、AAPへのリクエストが成功（200番台）しているかどうかも確認できます。失敗している場合は、Webhook URL・Secret Tokenの設定、AAPからGitLabへ／GitLabからAAPへのネットワーク到達性を確認してください。

## Section 2: .gitlab-ci.ymlでのansible-lintチェック

リポジトリへのpush時に、AAPへSyncするだけでなくPlaybookの静的解析を自動実行しておくと、品質の低いコードがSyncされる前に検知できます。

### Step 1: .gitlab-ci.ymlを作成する

```yaml
# aap-training-content/.gitlab-ci.yml
stages:
  - lint

ansible-lint:
  stage: lint
  image: python:3.12-slim
  before_script:
    - pip install ansible-lint
  script:
    - ansible-lint site.yml
  rules:
    - if: '$CI_PIPELINE_SOURCE == "push"'
```

### Step 2: pushしてパイプラインを確認する

**方法A: git CLIで行う場合（基本）**

```bash
$ git add .gitlab-ci.yml
$ git commit -m "Add ansible-lint CI pipeline"
$ git push
```

**方法B: GitLab Web IDEで行う場合（代替）**

GitLab Project画面で「Web IDE」を開き、`.gitlab-ci.yml` を新規作成してStep 1の内容を貼り付け、「Source Control」アイコンからコミットメッセージ（例: `Add ansible-lint CI pipeline`）を入力して「Commit to main」をクリックします。Web IDEでのコミットでもパイプラインは通常通り起動します。

GitLabの「CI/CD > Pipelines」で、`ansible-lint` ジョブが実行され、結果（成功/失敗）が表示されることを確認してください。もし指摘が出た場合は、内容を確認してPlaybook/roleを修正してみましょう。

## Section 3: CI/CDパイプラインからAAPのJob Templateを起動する

[応用演習7](./ex7.md)・[応用演習8](./ex8.md)で学んだREST API/CLI連携を、GitLab CI/CDパイプラインに組み込みます。

### Step 1: GitLabにAAPのトークンを登録する

GitLabのProject →「Settings」→「CI/CD」→「Variables」で、以下の変数を登録します。

| 変数名 | 値 | Protect/Mask |
|---|---|---|
| `AAP_TOKEN` | [応用演習7](./ex7.md)で発行したAPIトークン | Masked推奨 |
| `AAP_API_ROOT` | `https://<AAPのURL>/api/controller/v2` | - |

### Step 2: .gitlab-ci.ymlにデプロイステージを追加する

```yaml
stages:
  - lint
  - deploy

ansible-lint:
  stage: lint
  image: python:3.12-slim
  before_script:
    - pip install ansible-lint
  script:
    - ansible-lint site.yml

trigger-aap-deploy:
  stage: deploy
  image: curlimages/curl:latest
  script:
    - |
      curl -sk -X POST \
        -H "Authorization: Bearer ${AAP_TOKEN}" \
        -H "Content-Type: application/json" \
        -d '{}' \
        "${AAP_API_ROOT}/job_templates/7/launch/"
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
```

**Note:** `job_templates/7/` の `7` は、[応用演習7](./ex7.md)で確認した `apply-baseline` のIDに置き換えてください。

### Step 3: パイプライン全体の動作を確認する

GitLabへpushすると、以下の流れが自動的に実行されることを確認してください。

```
GitLabへpush
  → ansible-lintジョブ実行
  → AAP Project Webhookによる自動Sync（Section 1）
  → trigger-aap-deployジョブが apply-baseline をAPI経由で起動
```
