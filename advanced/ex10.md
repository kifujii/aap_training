# 応用演習 10 - EDA Rulebook ActivationとController連携

この演習では、[応用演習9](./ex9.md)で作成したRulebookを拡張し、受信したイベントに応じて実際にAAPの **Job Template**（[応用演習4](./ex4.md)で作成した `verify-hosts`）を自動起動する仕組みを構築します。あわせて、外部システムからイベントを受け取るための **Event Stream** を設定します。

**前提条件:** [応用演習4](./ex4.md)、[応用演習9](./ex9.md)を完了していること

> **Note:** EDA関連のUI配置や設定項目名は、AAPのバージョンによって細部が異なる場合があります。本演習ではオブジェクトの役割を中心に説明します。

## Section 1: Rulebookの拡張

### Step 1: run_job_templateアクションを追加する

`rulebooks/notify_on_webhook.yml` を編集し、点検を依頼するイベントを受けて `verify-hosts` Job Templateを起動するルールを追加します。

```yaml
---
- name: 点検依頼イベントを受けてverify-hostsを起動する
  hosts: all

  sources:
    - ansible.eda.webhook:
        host: 0.0.0.0
        port: 5000

  rules:
    - name: 点検依頼イベントで検証Jobを起動する
      condition: event.payload.status == "success"
      action:
        run_job_template:
          name: verify-hosts
          organization: "Default"
          job_args:
            limit: "{{ event.payload.host | default(omit) }}"
```

| 項目 | 説明 |
|---|---|
| `run_job_template` | AAPのJob Templateを起動するEDAアクション |
| `name` / `organization` | 起動対象のJob Template名とOrganization名 |
| `job_args` | Job起動時に渡す追加パラメータ（Limit、Extra Vars等） |

### Step 2: GitLabへpushする

**方法A: git CLIで行う場合（基本）**

```bash
$ git add rulebooks/
$ git commit -m "Add run_job_template action to rulebook"
$ git push
```

**方法B: GitLab Web IDEで行う場合（代替）**

GitLab Project画面で「Web IDE」を開き、`rulebooks/notify_on_webhook.yml` の内容をStep 1の内容に書き換え、「Source Control」アイコンからコミットメッセージ（例: `Add run_job_template action to rulebook`）を入力して「Commit to main」をクリックします。

## Section 2: Decision Environmentの確認

**Automation Decisions > Decision Environments** を開き、デフォルトのDecision Environmentが存在することを確認します（カスタムDecision Environmentの作成方法は[応用演習6](./ex6.md)のカスタムEE作成と同様の考え方で、`ansible-builder` で `ansible-rulebook` を含むイメージをビルドします。本演習ではデフォルトのものを使用します）。

## Section 3: Controller接続用Credentialの作成

`run_job_template` アクションがAAPのJob Templateを呼び出すには、接続先・認証情報が必要です。

### Step 1: Credentialを作成する

**Credentials**（Automation Decisions側のCredential一覧、または共通のCredential一覧）→「Add」で以下を入力します。

| 項目 | 入力値 |
|---|---|
| Name | `eda-controller-connection` |
| Credential Type | `Red Hat Ansible Automation Platform`（または同等の「Controller接続用」Credential Type） |
| Host | AAPのURL |
| Username / Password（またはToken） | [応用演習7](./ex7.md)で発行したAPIトークン等、Job Template起動権限を持つ認証情報 |

## Section 4: Projectの登録（EDA側）

バージョンによっては、Automation Decisions側でも同じGitLabリポジトリを指すProjectの登録が必要です。[基礎演習4](../basic-controller/ex4.md)で作成したものと同じSCM URL・Credentialを使って、Rulebookを配置したGitLabリポジトリを参照するProjectを用意（または既存Projectとの共有設定を確認）してください。

## Section 5: Event Streamの作成

外部システム（監視ツール等）からWebhookを受け取るためのエンドポイントを作成します。

### Step 1: Event Stream作成画面を開く

**Automation Decisions > Event Streams** →「Add」で以下を入力します。

| 項目 | 入力値 |
|---|---|
| Name | `check-webhook-stream` |
| Event Stream Type | `Webhook` |
| Credential | Webhook受信の認証方式（Basic/Tokenなど）に応じたCredentialを指定 |

保存すると、外部から呼び出すためのWebhook URLと認証情報（トークン等）が発行されます。これらを控えておいてください。

## Section 6: Rulebook Activationの作成

### Step 1: Rulebook Activation作成画面を開く

**Automation Decisions > Rulebook Activations** →「Add」で以下を入力します。

| 項目 | 入力値 |
|---|---|
| Name | `deploy-notification-activation` |
| Decision Environment | Section 2で確認したもの |
| Project | Section 4で確認/作成したProject |
| Rulebook | `rulebooks/notify_on_webhook.yml` |
| Credentials | `eda-controller-connection`（Section 3） |
| Event Streams | `check-webhook-stream`（Section 5） |

「Save」をクリックすると、自動的にRulebookの稼働が開始されます（ステータスが `Running` になることを確認してください）。

## Section 7: 動作確認

### Step 1: Event StreamのURLへWebhookを送信する

```bash
$ curl -X POST "<Event StreamのWebhook URL>" \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <Event Streamの認証トークン>" \
    -d '{"status": "success", "host": "srv1"}'
```

### Step 2: Job Templateが自動起動されたことを確認する

**Automation Execution > ジョブ** を開き、`verify-hosts` のJobが新たに実行されていることを確認してください。Jobの詳細画面で、制限に `srv1` が反映されていることも確認してください。

### Step 3: Rulebook Activationのログを確認する

`deploy-notification-activation` の詳細画面 →「Output」タブ（または同等のログ表示）で、受信したイベントとアクション実行のログを確認できます。

## Section 8: 後片付け

研修終了後、意図しないJobの自動起動を避けるため、`deploy-notification-activation` を「Disable」（無効化）しておきましょう。
